# Git Workflow Documentation

## Project
Build a Version-Controlled DevOps Project with Git.

## Objective
Manage a DevOps project using Git and GitHub best practices.

## Branch Strategy

- main: Stable and final project code.
- dev: Development and integration branch.
- feature: New feature development branch.

## Git Commands Used

1. git init
2. git add
3. git commit
4. git branch
5. git switch
6. git push
7. git pull
8. git merge
9. git tag
10. git stash

## Development Workflow

1. Initialize the Git repository.
2. Create a GitHub repository.
3. Create main, dev, and feature branches.
4. Make changes in the feature branch.
5. Stage and commit changes.
6. Push changes to GitHub.
7. Create a Pull Request from feature to dev.
8. Merge feature into dev.
9. Create a Pull Request from dev to main.
10. Merge dev into main.

## Version Control

Created project version tag:

v1.0.0

## Best Practices

- Use meaningful commit messages.
- Keep branches organized.
- Use Pull Requests for code reviews.
- Never commit passwords or API keys.
- Maintain project documentation.
